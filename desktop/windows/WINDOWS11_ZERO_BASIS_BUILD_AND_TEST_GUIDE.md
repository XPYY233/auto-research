# Auto Research Windows 11 内部预览：零基础构建与测试手册

> 适用对象：第一次参与软件内测、不会配置开发环境的用户。
> 适用范围：个人 Windows 11 x64 测试电脑。
> 重要：这是内部预览流程，不是未来正式用户的分发方式。

## 0. 只认这个交付文件夹

OneDrive 最终目录约定为：

```text
Auto Research Windows Internal Preview\YYYY-MM-DD\
```

只有目录内出现 `READY.txt` 后才开始。它必须同时包含：

```text
READY.txt
SHA256SUMS.txt
WINDOWS11_ZERO_BASIS_BUILD_AND_TEST_GUIDE.md
Auto-Research-Windows11-x64-internal-YYYYMMDD-Setup.exe
Auto-Research-structured-evidence-internal-YYYYMMDD.aresearch
```

如果今天必须在你的 Windows 电脑本地生成内部预览，还会额外包含：

```text
生成今日内部测试版.cmd
build-source.zip
```

缺少 `READY.txt`、哈希文件、安装包或资料包中的任何一个，都不要继续，也不要从其他目录拼文件。

## 1. 开始前确认电脑

1. 打开 **设置 → 系统 → 系统信息**。
2. 确认“Windows 规格”写着 Windows 11。
3. 确认“系统类型”包含“64 位操作系统”或“x64”。
4. 确认系统盘至少有 8 GB 可用空间。
5. 等 OneDrive 把整个测试文件夹同步完成：文件图标不能仍显示转圈。

不要提前安装 Python、Git、Node、数据库或 Visual Studio；也不要修改环境变量。

## 2. 核对文件没有损坏

1. 打开测试文件夹。
2. 在文件夹空白处按住 `Shift` 并点击鼠标右键。
3. 选择“在终端中打开”。
4. 复制下面命令并按回车：

```powershell
Get-FileHash .\Auto-Research-Windows11-x64-internal-YYYYMMDD-Setup.exe -Algorithm SHA256
Get-FileHash .\Auto-Research-structured-evidence-internal-YYYYMMDD.aresearch -Algorithm SHA256
```

5. 把两行 `Hash` 与 `SHA256SUMS.txt` 对应内容逐字比较。

只要有一个字符不同，立即停止并反馈“哈希不一致”。不要尝试安装或解压。

正式交付时，文件名中的 `YYYYMMDD` 会替换为真实日期；请直接复制文件名，避免手打。

## 3A. 已有 Setup.exe：直接进入安装

如果文件夹里已经有 `...-Setup.exe`，跳到第4节，不运行任何构建脚本。

## 3B. 只有构建入口：在 Windows 上一次性生成内部预览

只有 `READY.txt` 明确写着“需要本机构建”时才执行本节。

1. 双击 `生成今日内部测试版.cmd`。
2. 出现蓝色或黑色窗口后不要输入命令，等待它自动执行。
3. 第一次运行需要联网下载固定版本的构建工具，时间可能较长。
4. 正常结束时窗口必须明确显示：

```text
BUILD OK
Windows tests: PASS
Installer candidate: READY FOR LOCAL TEST
```

5. 生成的安装包会放在同一目录的 `output` 文件夹，并同时生成新的 `SHA256SUMS.txt`。

以下任一情况都要立即停止并截图：

- 要求你手动安装 Python、Git、Node 或 Visual Studio；
- 要求修改系统环境变量或 PowerShell 全局执行策略；
- 弹出管理员密码；
- 显示 `BUILD FAILED`、红色错误或窗口突然消失；
- 要求关闭 Windows Defender、防火墙或 SmartScreen。

构建脚本只允许为这一次任务使用临时环境，完成后不能要求你维护开发环境。

## 4. 安装内部预览

1. 双击 `Auto-Research-...-Setup.exe`。
2. 内部预览可能尚未购买正式代码签名证书，因此 SmartScreen 可能提示“Windows 已保护你的电脑”。
3. 只有同时满足以下条件时，才点击“更多信息 → 仍要运行”：

   - 文件来自本手册指定的个人 OneDrive 文件夹；
   - SHA-256 与 `SHA256SUMS.txt` 完全一致；
   - `READY.txt` 明确标记该文件为当日内部预览。

4. 不要关闭 SmartScreen，不要把文件加入 Defender 白名单。
5. 安装范围应为“仅当前用户”，正常情况下不需要管理员密码；出现意外管理员请求就取消。
6. 安装完成后从开始菜单打开 **Auto Research**。

## 5. 首次启动与导入资料包

首次启动应该直接显示“导入资料包”，不要求选择源码目录，也不要求 API key。

1. 点击“选择资料包”，选择同一交付目录中的 `.aresearch` 文件；也可以把这个文件拖入窗口。
2. 一次只选一个文件。
3. 正常进度依次显示：

   - 检查文件；
   - 验证资料包；
   - 安装；
   - 准备离线搜索；
   - 完成。

4. 超过几秒时，界面应该说明正在复制、验签、核对哈希或准备搜索，不能只显示无限转圈。
5. “激活”开始前允许取消；进入“准备离线搜索”后不要强制关闭程序。
6. 成功标志必须是“资料包已准备好，可以离线搜索”。

失败时不要反复导入。记录界面的错误码和所处阶段；错误提示不应显示你的完整本机路径。

## 6. 不配置 API key，先测试离线搜索

依次搜索以下三类内容：

1. 一个材料名，例如“钨”；
2. 一个实验量，例如“硬度”；
3. 一个条件问题，例如“300 K 附近的实验数据”。

检查：

- 能返回结构化证据；
- 结果明确显示来自官方资料包；
- 文献证据仍只有条目、结论、表格、图片四类；
- 没有本机路径、Zotero key 或开发者信息；
- 没有 API key 时，离线搜索仍然可用。

## 7. 配置自己的 DeepSeek key

只有测试 AI 提取或图书管理员时才需要 key。

1. 在软件设置中打开“AI 服务 / DeepSeek”。
2. 阅读“哪些内容会发送给 DeepSeek”和可能产生的费用。
3. 粘贴你专门用于测试的 key 并保存。
4. 软件不得把 key 显示回完整文本，也不得要求保存到文件。
5. 关闭并重新打开软件，确认 key 状态仍显示“已配置”。

不要在截图、反馈文档或聊天中发送完整 key。

## 8. 上传真实 PDF 并测试提取

1. 选择一篇你有权使用、可以正常打开的真实 PDF。
2. 点击“上传论文”。
3. 确认论文身份、题目或 DOI；识别错误就停止，不要继续付费提取。
4. 启动质量提取。
5. 检查过程明确区分处理中、需要确认、已完成和失败。
6. 完成后检查数值、意义、单位、题目、DOI、文章解释以及页码/原文定位。
7. 关闭并重新打开软件，确认上传论文和结果仍在私人库，且没有混入官方资料包。

不要用隐私论文或不能上传给 DeepSeek 的材料做首次测试。

## 9. 完整验收清单

| 流程 | 成功标志 |
|---|---|
| 下载 | OneDrive 文件全部同步完成 |
| 哈希 | 安装包和资料包 SHA-256 完全一致 |
| 安装 | 不配置开发环境即可安装 |
| 首次启动 | 直接进入资料包导入 |
| 导包 | 五步进度完成，旧资料不受影响 |
| 离线搜索 | 无 key 也能找到官方证据 |
| BYOK | key 进入 Credential Manager，不回显 |
| 上传 | 真实 PDF 身份可确认 |
| 提取 | 结果保留单位、页码和原文证据 |
| 重启 | 官方包、私人库和对话状态仍正确隔离 |
| 双开 | 第二个程序阻止同时写入同一工作区 |
| 卸载 | 不应静默删除私人数据 |

复制下面内容填写：

```text

安装包文件名：

界面错误码：

```

截图前遮住 API key、真实用户名、完整路径、私人论文正文和个人信息。

## 11. 任何时候遇到这些情况都立即停止

- 哈希不一致；
- 安装包来源不是指定 OneDrive 文件夹；
- 要求关闭安全软件；
- 要求管理员密码但手册没有说明；
- 要求输入 Auto Research 编辑密码；
- 要求选择源码、数据库或项目目录；
- 界面显示本机完整路径、API key 或私人标识；
- 导入失败后原有资料库无法使用；
- 上传或提取的论文身份不正确。

停止后保留窗口，不要自行删除 `%LOCALAPPDATA%\Auto Research`；按反馈模板记录即可。
