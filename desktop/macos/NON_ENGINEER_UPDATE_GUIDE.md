# 给非软件工程背景使用者的桌面版更新指南

这份说明只回答一个问题：另一个 Codex 对话完成一次功能优化之后，你怎样安全地让桌面软件获得这个功能。

## 先理解三个东西

你可以把项目想成实验室中的三层设备：

| 层 | 类比 | 更新时怎么处理 |
|---|---|---|
| 证据数据库和 PDF | 原始样品与实验记录 | 永远先保护，不能被软件更新覆盖 |
| `src/` 核心功能 | 仪器内部电路 | Codex 修改、测试、提交 |
| `Auto Research.app` | 仪器外壳和操作面板 | 从已经测试的核心重新构建 |

重新构建应用并不重新提取论文，也不修改证据记录。它只是把当前已经验证的程序装进一个新的 Mac 外壳。

## 每次功能迭代后的标准动作

### 第一步：让功能对话真正收尾

要求负责功能的 Codex 明确回答：

1. 改了哪些文件；
2. 跑了哪些测试；
3. 是否修改数据库或抽取产物；
4. 是否已经提交；
5. 当前 `git status` 是否干净。

不要只听“功能已经完成”。“代码写完”“测试通过”“已经进入桌面应用”是三件不同的事。

### 第二步：不要在两个对话同时写核心时更新应用

如果一个 Codex 仍在编辑，`git status` 会显示未完成文件。安全更新入口会主动停止。这不是故障，而是防止把半成品装进应用。

浏览器工作台、导师只读和 ngrok 已经退役。如果旧服务或另一个 Codex 的临时测试服务仍在运行，桌面版和更新入口会主动停止。请等测试对话结束，不要强制结束不属于当前工作的进程。

你只需要告诉正在工作的 Codex：

> 请完成当前改动、运行项目规定的测试、只提交你负责的文件，并告诉我工作树中剩余文件属于谁。

### 第三步：双击“更新桌面版.command”

入口会依次执行：

1. 检查项目是否仍有并行未提交改动；
2. 用 SQLite 在线备份机制复制当前证据库；
3. 运行桌面层测试和核心测试；
4. 检查 Python、前端 JavaScript 和数据库健康；
5. 构建候选 `Auto Research.app`；
6. 用只读冒烟检查确认候选能找到真实数据库和唯一前端；
7. 比较检查前后的数据库 SHA-256；
8. 把旧应用移动到 `releases/`，再采用新应用。

任一步失败，已有应用和原始证据都不会被新候选覆盖。

### 第四步：亲自做一个两分钟验收

打开新应用后检查：

- 搜索页能打开；
- 输入一个熟悉的查询能返回数据；
- 一条记录能打开原文证据；
- CSV 或 Excel 能实际下载到 Mac；
- 图书管理员失败时精确检索仍能使用；
- 关闭应用后窗口和后台进程消失。

这是软件中的“实验复现”：自动测试负责大范围检查，你负责确认最重要的真实体验。

## 出现问题时怎么回退

不要删除数据库，也不要重新抽取论文。

1. 关闭新应用；
2. 打开 `desktop/macos/releases/`；
3. 双击上一版 `.app`；
4. 把错误现象、新旧版本和操作步骤告诉 Codex。

更新前数据库备份在 `/Users/USER/Zotero/auto-research-backups/`，但普通界面问题通常只需要退回旧应用，不需要恢复数据库。

## 你每次可以这样要求 Codex

> 这次功能优化完成后，请按 Auto Research 的桌面更新规范检查：区分核心代码、用户数据和桌面壳；不要覆盖并行对话文件；只做一次联合全测；报告数据库是否变化；提交后只重建一次 macOS 演示应用；保留上一版和更新前数据库备份；最后用普通用户语言告诉我怎样验收和回退。

## 现在仍然不能混淆的结论

- 应用能启动：说明桌面程序可运行。
- 17/50 数据就绪：说明语料尚未完成原计划。
- 双路 DeepSeek 通过：不等于独立物理学人工确认。

三件事必须分别报告。
