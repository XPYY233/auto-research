# Mac 候选构建与更新说明

当前进度以 PROJECT_HANDOFF.md 为准。开发按 Issue → 分支 → PR → 自动检查 → 合并推进；普通源码提交不会自动更新已安装 App。

## 生成候选

在干净、已审查的开发仓库中双击 `更新桌面版.command`。入口会：

1. 检查未提交改动与已退役的旧编辑服务。
2. 使用与 App 相同的工作区选择规则，读取显式配置或默认 Application Support 工作区；选择无效时停止，不改用开发库。
3. 通过 SQLite 在线备份创建权限为 0600 的独立数据库副本，校验完整性、计算哈希后才登记为备份；重复运行不会覆盖旧备份。
4. 运行统一工程检查，再从干净环境、哈希锁定依赖生成唯一候选，执行自包含冻结冒烟及签名检查。

备份在开发仓库同级的 `auto-research-backups` 目录。它只覆盖 SQLite，不等于 PDF、图像、私人库、密钥和加密历史的完整恢复归档。完整保护与恢复见 WORKSPACE_MIGRATION 和当前验收记录。

尚未建立资料库的开发机器应使用 `build_app.command` 直接构建自包含候选；安全更新入口不会为了备份而初始化空库，也不会选择其他目录冒充现有资料库。

## 安装与验收

构建只生成 `desktop/macos/dist/candidates/<candidate_id>/Auto Research.app`，便捷链接指向最新成功候选。**这不会替换 `/Applications` 中的 App。**

维护者应核对候选清单、源码提交和哈希，保留已安装 App 回退副本，使用同一候选进行验收与事务安装。核心验收包括导入、提取、审核、发布、检索、真实导出、重启和失败恢复；缺失项目如实登记。验收通过后封装同一份 App，不重新构建替代，不覆盖历史候选。

安装前后需核对科研记录与来源文件；备份存在不等于已通过恢复演练。出现问题先保留现场并回退已验证 App，不能直接用旧数据库覆盖新研究数据。

第二台干净 Mac、人工科学金标准、分发许可与签名/公证状态分别验收；源码测试通过或候选可打开不代表正式交付完成。
