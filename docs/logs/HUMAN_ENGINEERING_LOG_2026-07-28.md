# 人类工程师日志：图书管理员与搜索性能阶段

## 用户问题

导师反馈指出：完整自然语言句子经常搜不到，必须手工拆成多个关键词；关键词查询接近 1 秒，文献继续增加后可能失去可用性。用户决定先修性能，再加入一个以 DeepSeek 为模型的“图书管理员 Agent”。

## 本次交付

- 搜索页默认入口改为“问图书管理员”，用户可直接描述研究问题。
- “精确检索”保留为进阶入口，原数据、表格、图片、实验结论四种模式全部保留。
- 新增 Search V2 可重建索引；没有改变原六列、证据、图表或校对历史。
- 图书管理员只组合四类既有结果，引用格式为 `[R编号]`，可继续打开详情与原文证据。
- 本地和公网端使用同一页面、同一数据库、同一 Agent；公网仍为只读权限。
- 新增全量重建、性能基准和论文级增量刷新接口。

## 实测结果

- 改造前代表性查询约 0.98–1.18 秒，中文整句可能返回 0 条。
- Search V2 最终代表性查询约 0.018–0.064 秒；“高熵合金在中子辐照后硬度如何变化”与关键词写法使用相同核心条件。
- 真实 DeepSeek 联调完成 6 次受控工具调用，能指出库内缺少“高熵合金中子辐照”的直接数据，并把离子辐照证据明确标为参考，未混淆实验类型。
- 全量索引当前包含 4,370 个对象：3,142 个数值事实、937 条实验结论、59 个表格、232 幅图片。
- 191 项自动测试、SQLite 完整性、原文高亮、CSV/Excel 和只读权限回归全部通过。

## 回退方式

- 页面切换到“精确检索”即可绕过 Agent；DeepSeek 失败不会影响本地搜索。
- 搜索索引可删除并重建；不会损失科学数据。
- 预改造 Git 标签：`evidence-demo-2026-07-28-pre-search-agent-baseline-1`。
- 预改造数据库和 Git bundle 位于 `/Users/USER/Zotero/auto-research-backups/`。

## 尚未改变的边界

- 固定 50 篇语料仍只有 17 篇数据就绪；本次没有伪造数据补齐语料。
- Agent 不是联网学术搜索器，只检索当前数据库。
- 系统仍不从图片像素推测曲线精确点。
- 自动质量门不等于物理学人工金标准。

## 图书管理员工作台第二阶段

### 用户体验

- 图书管理员现在始终检索整个文献库，页面不再要求用户判断“全部文章还是部分文章”。需要限定论文时使用右侧“精确检索”。
- 历史对话保存在当前浏览器，可搜索、恢复和删除。重新打开旧对话不会消耗 DeepSeek；继续追问时只提交最近有限对话。
- 返回结果改为横向“条目、表格、图片、结论”四类切换，不再把所有卡片纵向堆在一起。
- 检索期间显示当前阶段、已经过秒数和进度；书架中的角色改为用户的 Codex 宠物。动效关闭偏好下会自动停止。
- DeepSeek 返回的标题、粗体、列表和表格会按正式中文内容排版，不再显示 `##`、`**` 或表格竖线。

### 异常修复

- 真实使用中复现了 DeepSeek 把内部 DSML 工具代码直接放进回答的问题。该内容原本只应由后台执行，前端不应显示。
- 后端现可识别并执行合法 DSML 检索；内部代码不会保存为可信答案，也不会再次发给模型。
- 同时发现第二类风险：模型可能沿用历史中的 `[R编号]`，却没有为本轮返回对应证据。现在每轮强制至少进行一次新检索，旧的孤立引用回答会被页面停止展示。
- 工具检索与中文总结拆成两个阶段。若工具阶段不能正常结束，独立 JSON 总结通道会基于已收集证据生成回答；再失败时才显示明确的安全降级说明。

### 验证结果

- 修复前的异常历史已在页面中安全隐藏，原问题重新查询后返回正常中文总结，无任何 DSML 代码。
- 真实查询绑定了可打开的图片和实验结论结果；结果标签数量与服务返回一致。
- 全量 193 项自动测试通过；数据库健康、自检、Search V2 性能、CSV/Excel 和原文证据定位通过。
- 本阶段只修改 Agent 运行和页面交互；没有重新抽取论文，没有改变六列数据、图表或审核状态。
