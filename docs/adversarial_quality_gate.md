# DeepSeek 对抗式抽取质量门

## 目标

新论文的自动抽取不再由一次模型输出直接决定是否进入搜索。系统使用两次相互独立的 DeepSeek 扫描形成对照，再对低分项执行第三次复核；只有通过自动质量门或人工采用的候选才会发布。

## 流程

1. 本地程序读取真实 PDF 文字层，并用现有 PyMuPDF 链路建立或复用图表截图。
2. DeepSeek A 以“完整性审计员”角色扫描数据、定性结论和图表图注语义，重点减少遗漏。
3. DeepSeek B 以“精确性审计员”角色独立扫描同一原文，重点排除单位、样品、实验条件和证据关系错误。
4. 系统按数值、单位、物理意义、样品/条件、页码、表图编号和短原文证据逐项配对，保留较强版本和另一分支版本。
5. 每个候选计算一致性、事实支持、字段完整度、证据位置和综合分。默认自动发布阈值为 85 分。
6. 双路同时支持且达到阈值的候选以 `dual_pass` 发布。
7. 其余候选由第三次 DeepSeek 直接对照原文页复核；达到阈值的以 `third_pass` 发布。
8. 仍未通过的候选进入 `manual_review`，不会出现在搜索和导出中。人工采用后成为 `manual_approved`；不采用则保留为 `rejected`。

## 得分含义

综合分不是论文结论可靠性的评分，也不是绝对召回率。100 分表示该候选在机器可检查范围内具有完整字段、强原文证据和两路一致结果。两个模型仍可能共同漏掉同一事实，因此系统保留覆盖缺口扫描、原文证据入口和人工修正能力。

## 图表边界

- 图表截图、页码、边界、哈希和 PDF 跳转继续以现有本地稳定链路为准。
- DeepSeek 只读取图号、图注和相邻正文，不能声称看到图像像素。
- 系统不自动生成曲线数据点。
- 新语义候选失败时，不隐藏既有稳定截图；新发现但未通过的图表对象不进入搜索。

## 用户界面

- “对抗式质量提取”显示实际处理阶段和进度。
- “质量待审”集中展示仍需研究者判断的候选，不与普通六列校对混在一起。
- 搜索页的四种模式都可按质量来源筛选，并显示质量标签。
- 历史稳定数据标记为 `legacy_stable`，继续可搜，无需为了启用新机制而重跑全部旧文章。

## 命令行

```bash
PYTHONPATH=src python3 -m auto_research.cli evidence-quality-run "<DOI 或题目>"
```

已经扫描过的文章需显式确认：

```bash
PYTHONPATH=src python3 -m auto_research.cli evidence-quality-run "<DOI 或题目>" --force-rescan
```

旧命令不带 `--commit` 时只生成单路诊断预览；带 `--commit` 时会转入同一质量门，不再直接写入搜索数据。
