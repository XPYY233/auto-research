# Auto Research 安全模型

本文定义内部桌面软件的安全基线。它不把“仅内部使用”视为可信边界；本机恶意进程、污染的论文/表格、误配置、意外导出、丢失设备和供应链变更都属于威胁。

## 需要保护的数据

| 等级 | 数据 | 默认规则 |
|---|---|---|
| S0 机密 | API 密钥、系统凭据、加密密钥 | 只进入操作系统凭据库或进程内存；不进 Git、SQLite、日志、导出或证据包 |
| S1 私密 | 用户信息、私人文献、PDF、个人实验数据、对话历史 | 默认只在用户设备；外发或共享必须逐项授权并明确接收方 |
| S2 内部 | 证据数据库、原文摘录、图表截图、质量审核记录 | 仅进入受控内部包；公开导出必须使用字段白名单和去标识化 |
| S3 可共享 | 明确批准的清洗后演示数据和公开 DTO | 仍需版本、完整性校验、来源和撤回路径 |

## 强制边界

- 桌面服务只监听 loopback，并以每次启动的高熵令牌建立 HttpOnly、SameSite 会话；未经会话认证的请求一律拒绝。
- DeepSeek 为外部数据接收方。首次调用前必须说明将发送的论文文本/问题范围、服务方和费用；不同意时保持纯本地搜索与校对能力。
- DeepSeek Bearer 密钥只能发送到受支持的 HTTPS `api.deepseek.com` 端点。环境变量不能把密钥重定向到任意代理或主机；如未来确需企业网关，必须经过单独威胁评审和显式代码变更。
- PDF、CSV、XLSX、模型输出和证据包均视为不可信输入。解析必须有大小/数量上限，拒绝宏、外部链接、实体扩展和路径穿越；不得执行公式、脚本或文档内指令。
- 官方资料包、用户选择论文导出和私人实验转移属于三个不同的信任域。用户自签名或仅提供 SHA-256 的文件不得进入官方仓库，也不得成为 Librarian 语料；具体发布、权利确认和攻击回归门见 `docs/PACKAGE_TRANSFER_SECURITY.md`。
- CSV 导出必须中和以 `= + - @`（含前导空白）开头的单元格，防止打开文件时触发表格公式。
- API 错误响应不得包含密钥、远端响应体、本机路径、SQL、堆栈或底层异常文本。
- 发布包、Git 差异和共享材料必须扫描凭据、本机路径、私人 PDF、生产数据库、截图、用户标识和日志。

## 授权的安全测试

安全测试仅限项目负责人明确控制的本地 App、临时数据库、测试证据包和合成数据。允许进行身份绕过、CSRF/Origin、路径穿越、恶意文件、公式注入、请求体耗尽、令牌篡改、凭据泄漏、日志泄漏、数据包篡改、权限降级和恢复/回滚测试。

禁止把测试流量发送到不属于项目的系统、真实用户设备或第三方账户；禁止使用真实机密制作攻击样本。可能破坏生产科学数据的测试必须先在临时副本中复现。

## 修复与发布门

安全问题按“可泄漏 S0/S1、可未授权写入、可执行代码、可破坏证据完整性、可造成拒绝服务”排序。修复必须包含攻击回归，且不得以明文降级、关闭校验或扩大公开 DTO 来恢复可用性。

安全发布至少要求：自动测试通过；临时环境攻击回归通过；生产 SQLite 未被安全测试修改；凭据与隐私扫描无命中；桌面会话、只读写拒绝、证据包签名/哈希、备份与回滚均完成验证。发现未关闭的高风险问题时不得声明稳定发布。

## 事件响应

疑似泄漏时立即停止相关发行或共享，保留只含必要元数据的证据，轮换受影响凭据，隔离受影响包/版本，确认数据范围和接收方，再修复与回归。未经确认不得把“删除本地文件”等同于完成撤回。
