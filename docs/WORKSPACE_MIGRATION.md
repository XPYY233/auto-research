# 工作区迁移

关联 GitHub #2、#10。迁移使用独立暂存目录，逐项登记论文、文档、图像和历史输出路径，比较文件哈希与科研记录后才原子发布。原工作区不修改；已存在的目标绝不覆盖。

维护者在开发环境执行：

```sh
.venv/bin/python scripts/migrate_workspace.py --source /path/to/old-workspace --destination /path/to/new-workspace
```

这一步只准备副本，不改变 App 的日常目录设置。迁移报告包含私人路径，随工作区保留，不提交 GitHub。私人数据库、加密历史、密钥及不可变官方包仍属于 Application Support；本命令不复制或改写它们。跨机器不得复用本机 API 凭据。

## 保护与恢复

- schema v12 校验、SQLite 一致性备份、所有非派生表逐记录比较；仅五个登记路径列允许不同；可选的旧哈希类型修复必须逐条留证并经过校正清单反向比较。
- 原文、图片与数据库登记哈希必须一致；未知来源冲突始终阻止迁移。已证明的旧采样签名类型错误可显式启用修复，须同时满足原签名精确复现、同篇同路径文档已登记当前完整哈希，旧/新值及佐证记录均保留在迁移报告。不能仅凭采样签名修复。
- 缺失必要 PDF 或图片、活动提取记录、额外未登记数据库、符号链接、源在复制期间变化均停止发布。
- 已经缺失的非必要历史输出单独登记，保留原历史记录。JSON 内嵌历史路径保持原字节，不进行全库替换。
- 进程中断只留下 `.目标名.migrating-*` 暂存目录；正常重试使用新暂存目录。确认无运行迁移后，维护者可以另行归档或清理遗留暂存区。
- 原子发布使用已验证的 macOS `renamex_np(RENAME_EXCL)`；文件及目录同步后发布，目标已存在时失败。
- 切换日常目录仍须关闭 App、复核迁移后是否新增数据、验证私人状态及断点兼容，并保留原 selector 回退材料。当前命令不提供自动激活。

## 2026-09-19 真实演练

首次演练被 27 条来源哈希冲突阻止。调查发现旧 `pilot.select_pilot` 把采集阶段的 `pdf_signature`（文件大小＋首尾各 1 MiB 的签名）误写入 `papers.pdf_sha256`。对全部 27 条精确复现该算法；同篇同路径 `documents` 已登记当前文件的完整 SHA-256。未来 pilot 导入现改为计算完整文件哈希。

显式启用校正后，当前真实库复制演练通过：21 个非派生表，535 个原数据文件，550 个来源引用；校正 27 个论文哈希类型，保留前值、后值、算法和文档佐证。除逐条登记的路径与哈希元数据外，数值、单位、来源内容、审核版本和时间戳不变。6 个原本缺失的历史输出如实登记。原工作区和日常设置未改动，副本尚未激活。

```sh
.venv/bin/python scripts/migrate_workspace.py --source /path/to/old-workspace --destination /path/to/new-workspace --repair-legacy-sampled-hashes
```

已通过合成回归：记录/数值/单位/审核保持、原目录离线后读取新 PDF、未知哈希不符拒绝、旧签名修复必须显式启用并有完整哈希佐证、修改未被采样的中部字节仍拒绝、迁移途中数据库修改拒绝、目标竞争不覆盖、进程中断与重试、额外数据库/活动提取/非空视觉暂存与符号链接拒绝。实际激活及私人断点兼容仍须单独验收。
