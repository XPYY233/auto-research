# 辐照实验数据证据库使用说明

这个数据库不是用来替代论文，而是把论文中的实验记录整理成可检索、可复查的形式。

## 用物理实验的方式理解数据库

一条证据链对应：

```text
论文 → 样品 → 一组辐照条件 → 一项测量结果 → 原文页码/表图
```

- `Paper` 类似实验记录本的封面，保存 DOI、Zotero key 和 PDF。
- `Material` 是实际样品，包括成分、制备和初始状态。
- `Experiment` 是一次辐照条件组合，不是整篇论文的笼统“实验方法”。
- `Measurement` 是一个可独立比较的观测量。
- `Evidence` 是该观测量在原文中的位置与必要短片段。
- `Review` 记录谁确认、修改或驳回了数据。
- `PendingTask` 明确记录系统目前不知道或不应该猜的内容。

同一篇论文可以包含多个样品、多个辐照条件和多条测量。不要为了做成“一行一篇”而把这些关系压扁。

## 四种证据类型

- `measured`：仪器或实验直接报告的测量量，例如纳米硬度、空洞尺寸。
- `derived`：由测量量进一步计算的量，例如硬化增量或比值。
- `calculated`：SRIM、FISPACT 或模型给出的条件/结果。
- `qualitative`：论文明确报告但没有可靠数值的现象，例如“未观察到位错环”。

数据库默认检索只显示人工确认的数据。若只关心直接实验值，再选择“直接测量”。

## 来源精度

- `exact_table`：正文或补充材料表格中的精确值。
- `exact_text`：正文句子明确给出的值。
- `trend`：作者只给出趋势或定性变化。
- `figure_only`：数值只存在于图中。首版不会自动猜点，需进入待读曲线队列。

## 首篇教学流程

1. 在“30篇语料”中确认论文确实包含辐照实验。
2. 程序按两页一组读取本地 PDF；只向 DeepSeek 发送当前页面块文字，不发送 Zotero 数据库。
3. DeepSeek 分别抽取方法/条件与结果/观察，再由独立验证提示复核；Codex 只负责项目开发。
4. 通过字段、页码、数值锚点、背景文献过滤和重复检查后，候选进入“核验队列”。
5. 补充页码或表图编号，判断证据类型，再确认、标歧义或驳回。
6. 每处理5篇，查看待办与新增字段；前10篇后核心结构保持稳定。

## 不确定时怎么做

- 不知道数值属于哪个样品：标记“条件有歧义”。
- PDF 是扫描件：建立 OCR 待办，不手工猜字段。
- 只有曲线：建立待读曲线待办，不把视觉估计当成精确值。
- 单位不明确：保留原文，不生成标准化单位。
- 论文与补充材料冲突：分别保存两条证据，不静默覆盖。
