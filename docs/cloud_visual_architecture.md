# 图表云端智能增强架构

## 目标与边界

本功能在不改变既有图表证据的前提下，引入 MinerU 云端结构解析和 DeepSeek 科学语义增强。稳定基线为 243 个图表（40 个表格、203 幅图片），分布于 30 篇论文；首批云端质量验证只使用固定 10 篇论文中的 91 个图表。

任何云端结果都先作为候选保存。原 `visual_assets` 行、截图、哈希、页码、图表编号和校对历史不可覆盖。

## 数据流

1. 系统以 PDF 指纹检查缓存；已有稳定截图不重新渲染。
2. MinerU 接收整篇 PDF，异步返回解析进度、图片资源、表格 HTML 和结构信息。
3. 系统把 MinerU 结果写入候选表，并尝试按论文、页码和图表编号匹配稳定资产。
4. DeepSeek读取图注、附近正文和结构化表格，为候选补充材料、条件、方法、物理量和证据解释。
5. 校对页并排展示稳定版和云端候选。用户对每个图表单独决定，不支持整篇自动替换。
6. 只有同时通过全局质量门和逐图表人工采用的候选，才会在 `hybrid` 模式下参与搜索展示。

## 运行模式

- `legacy`：只读稳定图表，是默认模式。
- `shadow`：稳定版继续生效，同时生成和展示云端候选。
- `hybrid`：仅合并通过质量门且人工采用的候选；其他图表继续使用稳定版。

系统不提供默认 `cloud-only` 模式。网络中断、超时、配额不足、压缩包损坏或候选质量不足时，自动保留稳定版。

## 数据表

- `cloud_visual_runs`：每次云端任务、阶段、页数进度、错误和结果目录。
- `visual_source_versions`：稳定来源、MinerU 来源、DeepSeek 解释和人工决定的版本关系。
- `table_structure_candidates`：表格 HTML、行列数、表头、脚注和单元格抽查数据。
- `visual_analysis_candidates`：图注、轴、图例、材料、条件、方法、类型和趋势来源。
- `cloud_visual_quality_evaluations`：十篇质量集的召回率、精度、单元格一致率、轴图例准确率和曲线点违规数。

## 科学证据规则

- 表格事实必须能追溯到表号、PDF 页码、行列位置、原始单元格文本和截图。
- 图片趋势只允许标为 `explicit_text` 或 `visual_interpretation`。
- `explicit_text` 来自图注或正文；`visual_interpretation` 只作为待核验图片说明。
- 禁止根据图片生成曲线数据点。所有 `curve_points`、`data_points`、`digitized_points` 和 `xy_points` 字段在入库前递归移除。
- 仅由视觉解释产生的精确数值会被拒绝，不能进入实验结论或数值数据。

## 强制质量门

启用 `hybrid` 必须满足：

- 十篇金标准上的图表召回率不低于稳定版；
- 云端新增候选精度至少 95%；
- 至少抽查 100 个表格单元格，原文一致率至少 95%；
- 适用图片的坐标轴和图例正确率至少 90%；
- 曲线点违规数为 0；
- 每个拟采用候选都已经过人工逐图表决定。

质量门由后端强制执行，不能仅通过修改页面选项绕过。

## 凭据与隐私

MinerU Token 仅写入 macOS 钥匙串服务 `auto-research-mineru`，不写入 Git、SQLite、`.env`、报告或日志。DeepSeek API 凭据沿用项目现有安全配置。云端解析会上传整篇 PDF，因此仅应处理用户有权使用并允许上传到第三方服务的文献。

## 测试范围说明

“30 篇”只表示稳定图表当前覆盖的论文总数；“10 篇”才是本阶段云端影子验证集合。只有十篇达到质量门后，才允许分批扩展到其余论文。
