# 资料包导出、转移与信任安全契约

状态：V1 发布门。适用于官方 `.aresearch`、未来的用户选择论文导出、私人实验转移和任何混合导出设想。

## 1. 三个信任域不得混用

| 类型 | V1 定位 | 允许进入的位置 | 签名与信任 | Librarian |
|---|---|---|---|---|
| 官方论文包 | 课题组发布的不可变只读语料 | `official-packages` 与 `OfficialEvidenceRepository` | 只信 App 内置、经过代码审查的课题组公钥；私钥不进入 App、包、Git、日志或用户数据 | 允许，且仍只读取官方文献 |
| 用户选择论文转移 | 用户明确选择的原文件转移；V1 不得伪装成官方包 | 独立 `user-transfer-packages/literature`；不得更新 official active selector | SHA-256 只检查文件一致性，不认证发送者；接收方必须看到风险提示并确认来源 | 禁止 |
| 私人实验转移 | 用户明确选择的原文件备份/定向分享 | 独立 `user-transfer-packages/personal`；不直接写私人仓库 | SHA-256 不提供发送者认证或保密性；必须说明传输渠道和文件内容风险 | 禁止 |

V1 不实现混合包。以后若确有需要，只能使用外层容器承载相互独立的官方引用分区和私人加密分区；两者保持独立 schema、来源身份、权利清单、签名/加密、冲突与删除语义，不得合并 SQLite、`ATTACH` 或共享内部主键。

## 2. V1 内容边界

### 官方论文包

- 仅包含显式发布清单中的论文元数据和四类公开证据：`item`、`finding`、`table`、`figure`。
- 每篇论文都必须出现在本次权利确认清单中。整库 SHA-256 只证明输入快照未变化，不能证明论文逐篇具有再分发权限，也不能代替清洗、签名或内容审计。
- 短摘录必须同时受单段、单篇、全包聚合预算约束，重复与分片不能绕过聚合上限。
- 默认不含论文 PDF、图片、表格截图或其他二进制资产。
- 官方 0.2/V1 论文包一律不包含论文 PDF。论文图表只有在未来逐项记录权利依据、接收范围、实体 UID、精确 SHA-256、媒体类型、尺寸和像素上限后才可考虑；文件哈希本身不是版权许可。

### 用户选择论文转移

- V1 只允许用户逐篇勾选 PDF；每个 PDF 都必须同时满足真实 `%PDF-` 内容、`.pdf` 文件名、`application/pdf` 类型、稳定 `paper_uid`、`redistribution_allowed=true` 和非空权利依据。缺一项即失败关闭。
- “全部论文”不是默认选项；没有逐篇权利确认的批量转移必须失败关闭。
- 逐篇权利声明是用户本次操作的声明，不是课题组背书，也不能因为 SHA-256 匹配而自动变成版权许可。
- 输出只能进入 `user-transfer-packages/literature`；不得调用官方 importer、不得更新 official active selector、不得进入 Librarian。
- V1 不自动加入论文截图、结构化证据数据库、原始表格或内部审核材料；如用户选择其他附件，仍应逐文件说明内容和权利，不能借 `attachment` 角色绕过 PDF 或图片门。

### 私人实验转移

- V1 只转移用户主动选择的 CSV/TSV/XLSX，并只作为未受信任原文件安装到隔离目录；不得把它们自动解释为 confirmed/indexable 记录，不得绕过正常安全预览、用户核验和私人仓库确认门。实验图片和其他附件延后到逐文件媒体/权利契约完成后再开放。
- 系统生成的私人结构化导出只能来自 `confirmed + indexable` 无路径投影。`previewed`、`draft_saved`、AI 建议、模型响应、暂存文件、导入 ID、草稿 ID、CAS 内部状态和私人仓库主键不得进入控制文件或结构化导出。
- SHA-256 只检查包内文件一致性，不提供保密性。V1 必须在导出和导入前明确提示：原文件会以可读取形式存在于包中，只能通过用户信任的渠道发送；敏感数据应先删除或等待未来的认证加密版本。

## 3. 身份、冲突、撤销

- `paper_uid` 必须由规范 DOI 或规范题目身份重算；`entity_uid` 必须由论文 UID、四类类型和规范 identity key 重算。调用者提供的裸 UID 不得覆盖规范身份；受控沿袭必须有签名约束的 lineage 记录。
- 同一 `source_id + entity_uid + content_hash` 重复导入是幂等操作；相同 UID 但不同内容必须隔离并报告硬冲突，绝不静默覆盖。
- 同 DOI 但身份不同只能提示人工判断；官方记录与私人记录永不互相覆盖。
- 离线文件无法真正远程删除。撤销只能通过 App 更新的官方签名者撤销清单、或本机用户信任列表阻止后续启用；不能承诺删除接收方已经复制的文件。

## 4. 导出与导入原子性

导出固定顺序：只读私有快照 → 规范身份与白名单投影 → 权利门 → 泄漏扫描 → 构建 → 签名/加密 → 自验证 → 原子发布。失败只能留下受控命名且可清理的临时文件，最终目标不得出现半成品。

导入固定顺序：私有快照 → 归档结构检查 → 签名者/信任域检查 → 哈希与清单 → 安全解压 → schema/身份/权利审计 → 冲突检查 → 原子激活。任何失败都不得改变现有官方 active selector、私人确认记录或当前搜索源。

归档至少拒绝：路径穿越、绝对路径、反斜杠路径、符号链接或特殊文件、重复成员、Unicode/大小写冲突、加密 ZIP 标志、异常压缩比、成员/总大小超限、校验清单缺失、短读、损坏 SQLite 和未知 schema。

## 5. 禁止进入控制文件、公开 DTO 和结构化导出的内容

- API key、签名私钥、凭据存储密文或密钥标识；
- 本机绝对路径、`file://`、localhost URL、Zotero/storage key、设备 key；
- 生产数据库原件、私人源数据库哈希、内部数字主键；
- 审核者身份、内部备注、模型 prompt/response、DeepSeek run、对话历史、研究状态 token；
- 未确认草稿、AI 建议、暂存文件和失败运行产物；
- 未逐项授权的论文 PDF 或截图。

用户主动选择的原始 PDF、CSV/XLSX 或实验附件属于传输包 payload，不等于经过上述清洗。界面必须在导出前展示文件清单、大小、逐篇 PDF 权利状态和“原文件不会被脱敏”的警告；导入后仍须按不可信输入处理。控制文件、日志和公开 DTO 不得泄漏这些文件的本机源路径。

公开 manifest 可以包含包内文件 SHA-256、内容指纹、schema、包版本和公开计数；不得把“SHA-256 已匹配”描述成“发送者可信”“内容安全”“版权已确认”或“资料包未被整体替换”。导入界面必须显示 `trusted_official=false`、`integrity=sha256-only` 和固定中文风险提示；若没有外部已知 SHA-256 或受信签名，接收者只能把它当作自己确认来源的未认证文件包。

## 6. 官方 0.2 构建发布门

官方 0.2 候选只有在以下条件全部满足后才能发布：

1. 使用审计过的只读稳定快照，不直接读取活动生产库；输入快照 SHA-256 仅用于固定输入。
2. 发布策略精确列出每篇论文，并记录结构化证据、短摘录和二进制资产的权利范围；没有逐篇确认时不得以“全部论文”构建。
3. 输出只包含 manifest/checksums/signature、distribution SQLite、rights 和 provenance；V1 的 PDF 与二进制资产计数均为 0。
4. 运行路径/凭据/内部 ID/草稿/AI 建议/模型记录泄漏扫描，所有未解释的清洗丢弃必须阻断发布。
5. 使用已登记的课题组发布私钥签名，并以 App 内置公钥和正式 `OfficialEvidenceRepository` 完成一次隔离导入、查询和回退验收。
6. 对最终文件而不是临时输入计算 SHA-256，记录包版本、manifest SHA、内容指纹、论文/四类实体计数和导入用时。
7. 归档攻击、签名/哈希失败、schema/身份/权利错误和同版本冲突均不得改变旧 active 版本。

当前内部预览构建器使用 `internal-preview-only` 并对稳定源快照做哈希绑定；这不足以自动证明任意 0.2 候选可对外或对全部论文再分发。0.2 的逐篇权利清单和最终产物扫描必须作为单独发布证据保存。

## 7. P0 攻击回归

- 任意用户自签包即使结构合法，也不能通过 official importer 或修改 official active selector；传入自定义公钥不得绕过内置信任策略。
- 逐篇权利集合必须与导出论文集合完全一致；SHA 匹配但缺少权利确认仍失败。
- PDF/二进制默认计数为 0；非空资产必须有逐实体权利白名单、精确哈希、媒体类型和尺寸校验。
- 公开仓库和包扫描不得出现路径、凭据、Zotero key、内部 ID、草稿、AI 建议、模型记录或私人源哈希。
- 系统生成的私人结构化转移只能选择 confirmed + indexable；任何草稿或 AI 建议字段均失败。用户主动选择的原始 CSV/TSV/XLSX 只能作为隔离、未确认原文件，导入后仍须重新预览和核验。
- 伪造 UID、同 UID 异内容、跨来源覆盖、同版本异包均隔离或拒绝；重复同包导入幂等。
- zip-slip、symlink、重复成员、压缩炸弹、哈希/签名/SQLite 失败都在激活前拒绝，且旧版本字节和 active selector 不变。
- 构建中断或源文件替换不能发布半成品，也不能把替换后的私密字节写入最终文件。

## 8. 2026-08-09 实施审查状态

当前 `transfer_package.py` 已满足以下核心边界：文献包/个人包类型和目录隔离；逐 PDF 权利声明与稳定论文身份；`trusted_official=false`；transfer 与 official 格式互斥；安装位于 `user-transfer-packages`；导出前未加密确认；导入前外部 SHA-256 与用户确认；源文件和包快照使用 `O_NOFOLLOW`/`fstat`；安装目录逐级链接检查；路径成员、链接、重复成员、压缩比例、清单/哈希、同版本冲突和失败清理；常见路径、凭据、内部字段和 AI 建议标记扫描。

在接入用户界面或纳入正式构建前仍有以下 P0：

1. 桌面桥必须完整保留 `expected_package_sha256 + checksum_ack`，并展示固定中文警告；不得由桥自动回填当前文件自己计算的 SHA，也不得把“包内校验通过”显示成“发送者可信”。独立 SHA 必须来自另一个受信渠道。
2. 原文件 payload 不会自动脱敏。当前扫描只能阻断已知高风险标记，不能证明任意 PDF/CSV/XLSX 不含姓名、未列入规则的秘密或其他敏感实验内容。界面必须在导出前显示文件清单、大小、未加密状态和“原文件不会脱敏”，由用户主动确认；不得把扫描通过描述成数据已匿名化。
3. 官方 `0.2` 构建器当前仍是 `internal-preview-only`：它从稳定快照派生论文集合并生成对应 allowlist，但这不是独立的逐篇版权审查记录。当前预览策略允许的短摘录上限最高为单篇 150,000、全包 8,000,000 字符，也不能在没有单独权利决策时被称为“短摘录发布策略”。没有由发布负责人保存的“候选论文集合 = 已批准论文集合”证据、明确且更窄的摘录预算、零未解释丢弃、零 PDF/二进制资产、最终包泄漏扫描和隔离导入/回退报告时，只能生成内部候选，不能宣称正式 `0.2` 已通过发布门。内部构建报告含本机输出路径和源快照哈希，只能留在维护者审计目录；对外摘要必须重新做无路径白名单投影。
4. 用户传输包当前仅是核心格式与攻击边界；在桌面入口、信任提示、导出文件清单、外部 SHA 交换方式、导入隔离目录和失败恢复完成端到端验收前，不得把它纳入稳定用户功能清单。

P1：认证加密、用户/设备签名和撤销、图片/非 PDF 附件的逐项权利声明、导入前磁盘余量检查，以及经过确认后把隔离原文件送入正常安全预览的产品流程。以上项目不得用“内部使用”“扫描通过”或“已有 SHA-256”替代。
